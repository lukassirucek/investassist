---
name: holding-outlook
description: For the top-15 holdings run news, company-news and press-release scans and give a sourced rise/fall/neutral lean for the next 28 days; logs calls for a track record. Part of every daily run.
---
Rules: a lean is a TILT from dated, sourced news, not a forecast and not advice. Never invent numbers or sources. Every driver needs a URL you opened with WebFetch and the date of the item. If there is no fresh news for a holding, say so and leave it neutral with low evidence; do not fill space with old articles. Date check: discard anything older than 45 days unless it is a still-valid structural fact (label it with its date); beware search hits whose page header date differs from the article date (read the article date in the text).

## Procedure (project root, `python3 -I`)
1. Pick the holdings: `python3 -I scripts/outlook.py top` writes `data/outlook/top15.csv` (rank, instrument, value, and three query groups: `q_news`, `q_company`, `q_press_release`, separated by ` || `).
2. Search: run the queries in parallel (WebSearch mode standard; several holdings share a topic, e.g. both S&P 500 ETFs, so search each distinct topic once). For single stocks also look for results dates, guidance, management changes, analyst moves. For loan and crowdlending platforms: platform news, home-market property and mortgage rates, central-bank decisions. Group by topic, not by ticker, to save calls.
3. Verify: WebFetch each candidate. Keep publication date and the concrete fact (number, level, decision). Some sites block fetching (robots.txt); use another source instead.
4. Cross-check against `data/signals/signals.csv` (active signals already carry sources for macro and company events) and `data/ledger/mail_events.csv` (platform mail). Reuse their URLs where the fact fits.
5. Write `data/outlook/raw/<date>_calls.json`, one object per top-15 instrument (exact name from `top15.csv`): `instrument`, `summary` (1-2 sentences, plain), `horizon_days` 28, optional `ref_price` + `price_ccy` (only if verified today), `drivers` [{text, direction pos|neg|neutral, weight 1-3, kind news|company|press_release|analyst|macro, source_url, source_date}], `catalysts` [{date YYYY-MM-DD, event}] (use identical wording for shared events: "FOMC decision", "ECB decision", "US PCE inflation", "central bank rate decision"), `risks` [text].
   Weights: 3 = hard fact that directly moves the holding and is not yet priced (guidance cut, regulation, default); 2 = clear fact or major analyst view; 1 = context or already priced (e.g. a hike that is 90 % priced). Do not double count one underlying event from two outlets. INFERENCE statements say so in the text.
6. Ingest: `python3 -I scripts/outlook.py ingest data/outlook/raw/<date>_calls.json <date>` then `python3 -I scripts/outlook.py missing <date>` (must print none). The script computes the score and lean (|score| >= 3) and caps evidence by number of sourced drivers and domains.
7. Track record: `python3 -I scripts/outlook.py due <date>` lists calls whose horizon ended. For each, WebFetch the price then and now (use the stored `ref_price`; if none, skip the row) and record `python3 -I scripts/outlook.py outcome <run_date> "<instrument>" <pct>`. `python3 -I scripts/outlook.py score` prints hit rates; the dashboard shows them.
8. Report: the dashboard (`build_dashboard_html.py`) shows the leans, drivers, catalysts and risks. In the final reply name only holdings that are not neutral and holdings with a dated catalyst within 7 days.
